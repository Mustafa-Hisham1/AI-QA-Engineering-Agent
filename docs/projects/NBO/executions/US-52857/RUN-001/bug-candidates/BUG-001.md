*The Bug Candidate as originally raised in RUN-001 follows, unchanged.*

## Description

Activating an Approved, Inactive Operating Country from the list opens a confirmation
dialog. The requirement says the record becomes Active **without** a confirmation step.

## Preconditions

- An Operating Country that is **Approved / Inactive** (RUN-001 used `AUT Opc Mnyftfxg`,
  created Approved by `ADMIN_ALL`, then deactivated by the Approver).

## Steps to reproduce

1. Log in as `OPERATING_COUNTRIES_APPROVER` and open *Admin Module → Operating Country*.
2. Select the **Inactive** filter, search for the record, and click **Search**.
3. Click **Activate** on the row.

## Expected result

The record becomes Active without a confirmation step (REQ-OPC-030 AC-10; TC-52857-039 step 6).

## Actual result (observed, confirmed)

A dialog **"Activate AUT Opc Mnyftfxg?"** opens — *"The record becomes active immediately. You can
deactivate it again later."* — with **Cancel** and **Activate Operating country**. Nothing is sent
until the dialog is confirmed (the only status PATCH at that point was the earlier deactivation).
After confirming, the record became Active and the toast *"Operating country activated
successfully"* was shown.

The same dialog was shown to `OPERATING_COUNTRIES_MAKER` on `AUT Opc Fybfrrhp` in TC-52857-040
(13:32Z), which does not assert this behaviour and is not linked here.

## Suspected root cause (unconfirmed)

The list's Activate action appears to reuse the same confirmation pattern as Deactivate. Whether
the confirmation is a deliberate UI decision (which D-01 would make expected) has not been
decided — no decision in `decisions.md` covers activation.
