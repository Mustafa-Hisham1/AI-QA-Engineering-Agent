## Description

The Edit form of an Operating Country whose Approval Status is **Rejected** offers a **Reject**
action. A Rejected record may only be approved again: the expected actions are exactly
**Approve** and **Cancel**.

## Preconditions

- An Operating Country in **Rejected / Inactive** state (RUN-001 used `AUT Opc Syhidmpu`, id 20050:
  created with Send For Approval by the Maker, rejected from the list by the Approver with remarks
  `Rejected by QA`).

## Steps to reproduce

1. Log in as `ADMIN_ALL` and open *Admin Module → Operating Country*.
2. Select **Inactive**, search for the Rejected record, and click **Edit**.
3. Inspect the actions in the form footer.

## Expected result

The actions are exactly **Approve** and **Cancel** — no Reject (TC-52857-037 step 3,
REQ-OPC-046 AC-2 for a Rejected record).

## Actual result (observed, confirmed)

The footer shows **Cancel**, **Approve** and **Reject** (subtitle *"You decide on this operating
country when you save."*). In the list, the same Rejected row offers only **Approve** to
`ADMIN_ALL` — the list and the Edit form disagree. Approving from the Edit form then worked:
*"Operating Country approved successfully"*, record Approved / Active.

Reject was **not** clicked, so what rejecting an already-Rejected record does was not observed.

## Suspected root cause (unconfirmed)

The Edit form appears to choose its actions from the user's permissions only (all-permission →
Approve + Reject), without considering the record's current approval status, whereas the list
row does consider it.
